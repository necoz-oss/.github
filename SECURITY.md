# Security

Necoz welcomes responsible reports of security vulnerabilities in its projects.

Give maintainers a chance to understand and fix a problem before it is discussed in public. Keep unpatched vulnerability details out of issues, pull requests, discussions, and other public channels. That includes exploit steps and proof-of-concept code.

## Report in private

Use **GitHub Private Vulnerability Reporting** when the affected repository has it enabled:

1. Open that repository on GitHub.
2. Open the **Security** tab.
3. Choose **Report a vulnerability**.

The report stays between you and the repository maintainers.

If **Report a vulnerability** is missing, private reporting is not enabled for that repository. Email [nyaonyao0725@gmail.com](mailto:nyaonyao0725@gmail.com) instead, and include the same details you would put in a private report.

Keep the report off public issues, pull requests, and discussions. A public post would expose an unpatched vulnerability.

Maintainers should enable [private vulnerability reporting](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately) on repositories that accept security reports. When a repository names its own private contact, follow that policy.

## What to include

When you can, include:

- The repository, and the version or commit you tested
- What the issue allows, in plain language
- Steps to reproduce, or a short description of the conditions
- The impact you know about

A clear description is enough. A full exploit is optional.

## After you report

Wait for a maintainer to reply through the private report, or through the email fallback when you used it. Hold public disclosure until a fix is available and you and the maintainers have agreed on what to share.

Response time depends on the maintainers of that repository. This organization does not set a deadline.

## Repository policies

A Necoz repository may define its own supported versions, scope, and reporting steps. Follow that repository's security policy when it has one. This file is the organization default for repositories that do not publish their own.
